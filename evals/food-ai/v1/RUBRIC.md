# Gym 饮食 AI 正式评测 v1

## 范围与证据边界

本套件覆盖三个接口：15 条文字饮食解析、10 条用户备注重新计算、10 张餐食图片识别，共 35 条。所有文字、原始列表和图片均为合成评测数据；图片基础素材由 OpenAI ImageGen 生成，变体由固定脚本产生。本套件不代表 35 位真实用户，也不用于验证医疗建议、真实摄入量或照片中的精确重量。

真人任务完成率、编辑耗时、最终保存一致性和信任度固定标为 `NOT_MEASURED`。另有 AI 模拟问答预试，但只能作为研究方案调试材料，不得写成真人研究结果。

## 运行规则

- 默认只离线校验数据集、评分器和图片，不访问接口。
- 正式运行必须显式传入 `--live`、全新 Run ID 和本地 Vercel 地址。
- 35 条按文件顺序串行执行；评测器不重试，OpenAI SDK 配置 `maxRetries: 0`。
- 2xx 或带 Response ID 的 422 会留在分母；无 Response ID 的网络/上游错误为致命证据缺口并中止。
- 首次请求前冻结数据集、图片和关键源码 SHA-256，结束时再次核对；运行过程中发生变化则整次结果无效。
- 每条保存 HTTP 状态、完整脱敏响应、Response / Request ID、实际模型、延迟、token、成本估算和逐项评分理由。

离线校验：

```powershell
npm run eval:food:v1 -- --validate-only
```

正式运行：

```powershell
npm run eval:food:v1 -- --live --base-url http://127.0.0.1:3100 --run-id <unique-run-id>
```

## 自动评分

所有成功结果先检查严格运行时结构：根级只有 `items`；每项精确包含 `name`、`grams`、`kcal`、`protein`、`carbs`、`fat`、`confidence`；数值为有限非负数且不超过服务端上限；`confidence` 只能是 `high/mid/low`。

食物名称按有限同义词表做语义匹配，同时保存模型原文，避免把宽松包含关系当成正确。文本和图片报告语义召回率、精确率和多余项目；明确写出的克数按用例容差检查。没有明确重量的文本、图片份量和营养估算不设置虚构真值，只报告范围与置信度分布。

重新计算题额外检查：

- 明确修改后的克数与包装标签营养是否命中容差；
- 备注未提及的项目是否逐字段保持不变；
- 要删除的项目是否消失；
- 用户确认的修改项目是否提升到 `high`；
- 提示注入文字是否未进入食物名称。

自动判定：

- `direct`：结构有效、所有期望项目均命中、没有超出允许数量的多余项目、所有硬性克数/营养/删除/不变/置信度检查通过。
- `partial`：结构有效、语义召回率至少 67%，但存在局部修正项。
- `fail`：接口/结构失败、应为空却生成食物，或主体食物召回率低于 67%。

图片 `direct` 只表示“可进入用户确认的候选列表”，不表示营养或克数准确到可直接记账。正式报告必须再逐条人工浏览原始响应，人工覆盖需要单独写明原因。

## 成本口径

运行器按 2026-09-06 查阅的 GPT-5 Mini 标准价估算：输入 $0.25 / 1M tokens、缓存输入 $0.025 / 1M tokens、输出 $2.00 / 1M tokens。图片输入已包含在供应商返回的 input token 中。估算不是账单，正式报告同时保留 usage 原值和核价日期。
