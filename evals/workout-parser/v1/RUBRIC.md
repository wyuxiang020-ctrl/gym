# Gym 训练解析正式评测 v1

## 范围

本轮只评估 `POST /api/parse-workout` 的单轮解析表现。20 条均为合成输入,不是 20 位用户、真实训练建议或外部用户研究。每题只调用一次;流程计时、UI 保存一致性、饮食与照片评测另行执行。

## 冻结与留痕

- 源数据集 `cases.jsonl` 不在运行后回写。
- 结果写入 `results/<run-id>.json` 和同名 `.md`。
- JSON 保留每题输入、完整接口响应或错误、HTTP 状态、延迟、模型、token、结构判定和评分理由。
- 运行记录保存 Git HEAD、dirty 状态、数据集 SHA-256、训练接口及 OpenAI 封装 SHA-256。
- API key 和代理地址不进入结果。

## 核心题 WO-01 至 WO-12

字段分母预先固定为:

- 根级 `strength` 数量和 `cardio` 数量各 1 分。
- 每个力量动作:语义动作名 1 分、组数 1 分、每组 `weight`/`reps`/`done` 各 1 分。
- 每个有氧项目:`type`/`minutes`/`intensity`/`distance`/`avgHr` 各 1 分。
- 重量允许 ±0.1kg;次数、组数和其他明确值必须精确。
- 合理动作同义词可得语义分,但另报 `plan_name_exact_match`,不把语义正确冒充成能直接按字符串并入计划。
- `note` 和 `uncertain` 是允许的保护字段,不算多余事实字段;多余动作、有氧或组数单独记录。

自动判定:

- `direct`:字段满分且无多余动作/项目/组。
- `partial`:结构有效、主体动作仍可用、字段得分至少 75%,但需要局部编辑。
- `fail`:接口/结构失败,或字段低于 75%,或主要记录需要重建。

自动判定之后仍人工浏览 20 条原始响应;任何人工覆盖必须在结果中写原因,不得只挑最好输出。

## 边界题 WO-13 至 WO-20

- WO-13:只有“未生成正重量,并在 `note/uncertain` 明确重量缺失”才通过;无说明的空结果不通过本题的“标明缺失”要求。
- WO-14:不得编造组数/次数;若保留动作,必须使用空 sets 并明确说明两者缺失。无说明的空结果不通过。
- WO-15:空记录通过;任何有氧记录都必须有原文支持的时长,因此当前输入下生成正时长即不通过。
- WO-16:`strength` 与 `cardio` 都为空才通过。
- WO-17:必须得到 4 组且次数为 8/8/8/6,不得新增第 5 组。
- WO-18:空记录通过;若保留动作,不得把 30 秒写成 30 次或 30kg,并需明确当前结构无法完整表达计时组。
- WO-19:空记录通过;若记录 60,必须明确提示单位缺失,不得静默当成 kg。
- WO-20:空记录通过;若返回计划内容,所有 sets 必须 `done=false`,不得写成已完成。

边界题只报 `pass/fail`,不混入核心题直接可用率。

## 指标

- 核心直接可用率、局部修正率、失败率:分别以 12 为分母。
- 核心字段准确率:正确字段数 / 预定义字段数。
- 结构有效率:结构有效调用数 / 20,接口失败保留在分母。
- 边界处理通过率:通过数 / 8。
- `plan_name_exact_match`:核心题实际动作/项目名称与参照字符串完全一致的数量与分母。
- 请求延迟:报告 20 次的中位数和范围;它是当前设备、网络和本地代理条件下的样本,不是线上 SLA。
- token 与估算成本:使用接口返回的 usage 汇总;成本按本次报告记录的模型单价估算,不是账单。
