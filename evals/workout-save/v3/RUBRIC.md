# Gym 保存流程 V3 评测口径

本版把验收边界从“接口能解析 JSON”延伸到“用户确认的字段实际保存并能重新打开”。V1 与 V2 的旧 20 条、原始响应、评分与中止记录保持不变，不按新规则回写旧成绩。

## 数据集与版本

- 历史回归：直接读取 `evals/workout-parser/v2/cases.jsonl` 的 20 条原文。它们已经参与过 Prompt 与 Schema 调优，不能称为独立测试集。
- 本轮开发用例：确定性软件测试与浏览器故障注入，均为合成输入，允许用于修复。浏览器固定响应不证明模型准确率，也不是真人研究。
- 冻结留出：`holdout.json` 的 8 条新合成输入，实施前冻结 SHA256 `a5dda8426f31344f64d58e9bade3ede7f18fd93d4fd22529e326afe20f75cbfe`。只在功能与开发测试完成后执行，不根据其结果在本轮调参。作者编写并见过输入，属于“未用于调优的作者留出集”，不是第三方双盲或真人独立测试。后续若据此修复，它将转为回归集。
- 每次真实运行使用新目录、独立尝试记录和请求响应文件。失败、未运行、耗时和费用未知均保留。评分器修改后只能新增复核，不改原分。

## 重量与完成的正确性

| 状态 | 存储值 | 有效完成 | 重量乘次数容量 |
|---|---|---|---|
| known | 明确单位换算的正数 kg，上限 1000 | 完成且次数或秒数有效时计入 | 仅次数型计入 |
| bodyweight | null，用户或原文明确自重无额外负重 | 可计入 | 不推测身体重量，因此不计入 |
| unknown | null，重量缺失或单位不明 | 不计入，AI 完成记录禁止确认写入 | 不计入 |
| not_applicable | null，明确不以公斤衡量 | 可计入 | 不计入 |

`done` 仍只表达是否做过，不承担重量已确认的含义。未来计划必须是 false 或安全空结果，不能作为已完成写入。不能仅因动作名为平板支撑便推断自重。旧题 WO-18 在 V3 应为 unknown/null 并待用户确认；这与 V2 的 0 占位口径不同，不进行跨版本总分提升比较。缺单位题允许原数值写在 note/uncertain，不允许直接当 kg。

老数据无 weightState 时：正重量且无明显重量/单位缺失提示暂按 known 兼容；0 或明确有歧义的旧值转为 unknown/null，原数值保留为 legacyWeight。不自动覆盖原始存储；下一次正常保存写标准化结构。没有有效完成组的条目热量清零。旧正数可能是历史默认值，本轮无法完全追溯，必须披露此限制。已有人工打卡不撤销。

## 分层评分

1. 传输层：HTTP、响应 ID、固定模型、结构有效性、每次尝试耗时、usage、估算费用。首个失败也是分母；中止后剩余标 NOT_RUN。120 秒总等待，无自动重试，手动重试新建运行。
2. 语义层：动作、组数、每组重量状态/数值、次数或秒数、完成状态；有氧类型、时长、距离、心率、强度及 done。旧题名称严格精确匹配，别名争议单独复核。数值换算容差 kg 0.05（旧回归）/0.01（留出）；组次必须精确。
3. 确认层：未补全未知值与未完成项目被阻止；编辑和批量应用不改无关字段；取消不新增；重试失败保留原文和已有预览；修改原文清空旧预览，避免错存。
4. 保存层：确认后读取真实浏览器 `gym-data-v1`，逐字段比对；刷新/重新进入后再比对；计划待完成数据允许保存但不计完成。重复导入需要明确决定，容量错误不能留下半批数据。AI 预览草稿与正式记录隔离。

最终“完整流程通过”必须同时包含第 3、4 层证据。解析通过率不等于保存正确率。固定响应测试是软件功能证据；真实 API 回放测试标注其来源与修正规则；真人任务另计。错误识别已被用户纠正也不能反记为模型首次正确。

## 成本与统计

保留所有尝试、首次失败、重试关系（本轮自动重试为 0）、总等待；无 usage 不填 0 费用，除非能证明调用前拦截。按官方模型页核对的 GPT-5 mini 单价估算：每百万输入 token $0.25、缓存输入 $0.025、输出 $2。来源 https://developers.openai.com/api/docs/models/gpt-5-mini ，2026-09-30 核对；这是估算，不是账单。费用保护代码不放宽。

真人编辑率、真人任务成功率、节省时间、饮食照片真实误差均为 NOT_MEASURED，直至完成配套脚本。模型 confidence 只保留作为未校准提示，不计作准确率。
