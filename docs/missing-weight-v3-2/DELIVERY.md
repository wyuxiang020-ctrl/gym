# Gym 缺失确认 V3.2 交付说明

2026-10-01。本轮完成“已完成但重量记不清”的确认保存，并仅附加改善现有动作详情到教学网页的路径。当前是本地 V3.2，尚未部署或替换任何线上版本。软件正确性已验证，是否让用户更愿意主动使用仍未验证。

## 目标与完成边界

以最新 V3.1 交付及实际工作区为基线，不重复实现四态重量、草稿恢复、取消、模板或预算保护。先冻结 77 个源码文件及 381 个已有文档/评测文件哈希，再实施改动。工作区原有大量未提交修改继续保留；本轮也没有 commit、push、部署、修改密钥或读取用户训练存储。

核心标准是：真实完成与信息完整分开；缺失必须显式确认，统计不冒充完整；确认、取消、保存失败、刷新、重新打开及导出导入保持一致。额外体验只改善已有教学资料入口与链接，不新增账号、社交、Agent、成长或新教学内容。

## 改动前后

| 场景 | 修改前 | V3.2 |
| --- | --- | --- |
| 确实做完卧推 8 次但忘记重量 | unknown 阻止整份 AI 预览保存，只能补全、删除或留草稿 | 点击“确认重量未记录”后可保存；weight 保持 null，确认状态随重开保留 |
| 未核对或模型伪造确认 | 无独立用户缺失确认 | 未核对仍阻止保存，模型字段不取得用户确认权限 |
| 已确认缺失但只是未来计划 | 不允许当已完成保存 | 继续阻止；确认缺失不会自动修改 done |
| 缺失组与 50kg×8 混合记录 | 无法按缺失事实完成整份保存 | 可保存混合记录；重量容量仅 400kg·次，显示“部分”，缺失组不进入当前热量估算 |
| 修改、复制或批量处理 | 没有缺失确认需要管理 | 改明确重量清标记，复制组不复制确认，批量填写清标记、撤销恢复；取消保留原值 |
| 网络或存储失败 | 原有恢复适用于旧有效记录 | 已确认缺失草稿也保留并可手动重试；不显示虚假成功 |
| 查动作资料 | 动作名称已有详情入口；视频区需要可播放的直链 | 增加明确“动作要领”入口，可收藏普通网页并主动在新标签打开；不替用户找直链 |
| 资料链接非法、保存失败或视频播放失败 | 缺少对应的完整处理 | 拒绝非法协议/凭证，保留原链接及编辑内容，视频可回到原链接 |

核心新增 `missingWeightConfirmed?: boolean`，只有 unknown/null 的 true 有确认语义。`resolvedWeight` 仍表示明确的重量状态；完成事实与估算资格分别判断。缺失组可用于训练完成和训练型打卡资格，不能以 0 或历史重量制造容量、重量纪录或有效估算输入。没有新增 PR 算法。现有 MET 公式未改，排除缺失组是保守产品口径，不表示实际没有消耗，也不是声称 MET 公式必须知道所举重量。

旧数据零值仍保守读取为 unknown，原值用于追溯，不自动写回或自动确认。确认保存在当前浏览器草稿/正式记录/备份中，不是跨设备账号功能。模型与 API、调用/预算保护源码均未变。

产品改动涉及 12 个既有文件，新增一个本地链接分类器：数据类型、重量逻辑、两类校验、重量编辑器、AI 预览、训练记录/保存、历史/月历显示、动作详情和版本标签。保留原 `exerciseVideos` 字符串结构兼容已有直链。

## 对不愿主动使用的判断

用户报告本人和朋友非强制时常不想使用，并会到外部查动作。这是重要的定性风险信号，样本人数、次数和情境尚不明确；不是量化留存或满意度测试。

已核对的实现事实与原因假设分开：

| 实现事实 | 待验证原因 |
| --- | --- |
| 产品主要路径是计划、记录与确认；用户明确说会查动作 | 用户当下需要“知道怎么做”，而不是“补一份记录”，任务可能错位 |
| 首次必须先建身体档案，首页默认打卡/宠物/月历 | 即时价值出现得较晚；打卡回报未必与训练决策相关 |
| 已有同名动作上次记录，但历史页主要是按日摘要 | 录入和核对成本立即发生，记录对下一次训练的具体帮助不明显 |
| 52 个库内动作都有静态详情，但没有来源/审校结构；示意图非真人姿态演示 | 外部真人示范可能更符合所需的信息形态与可信度 |
| 详情按精确名称关联，原视频要求直链 | 用户可能找不到对应资料，或者仍要自己重复查找；本轮仅解决链接类型和入口摩擦 |

因此可以说“当前对这些使用者的自发使用价值仍未成立”，不能确认“主要原因就是不可替代性低”。功能独有也可能没人需要；已有功能若及时解决重要任务，也可能被反复使用。查外部资料可以与记录工具互补，不要求 Gym 替代全部平台。收藏链接只是减少重新寻找入口的可行改进，尚未证明降低外搜次数或提高留存。

下一步建议停止加模块，先由作者在之后自然发生的 3 次训练机会中做轻量记录：当时想解决什么、是否自发打开、若没打开用了什么、这次记录是否在下一次被查看并影响了选择。三次只是探索安排，不是证明市场有效的样本量门槛；不要求强制使用或招募。未使用也是真实结果。若连续反馈主要是“想看动作、不需要日志”，重新选择目标用户或调整产品定位，再决定是否建设可追溯动作资料；不要用更多打卡、宠物或更强模型掩盖核心需求不匹配。

## 剩余限制与作品集结论

未知重量确认只代表用户主动承认缺失，不保证训练真的发生；模型仍会错，其他字段仍需核对。草稿限当前标签页，localStorage 不是云备份或多设备同步。已保存资料按精确动作名关联，别名未解决；外链可能失效/要求登录，教学内容未专业审核，当前演示动画不能代替姿态指导。新增资料输入在关闭弹层前未保存则不保证恢复。

直链视频通过常见文件扩展名识别；没有这类扩展名的地址按网页外部打开，不保证内嵌播放。只测 Edge 与 390px 模拟视口，未测真机 Safari、长期使用、自然复用、正式真人效率或真实餐食真值。保留 [既有真人脚本](../weekly-save-v3/HUMAN_TASKS.md)及未测状态，招募不是软件改进前置条件。本轮完成标准达到后停止扩展。

作品集可准确写：我把训练完成与数据完整度分开建模，让用户明确确认缺失后保留训练事实，同时排除相关统计；以实际存储、刷新重开和失败恢复验证，而不只检查 AI 输出结构。针对作者报告的动作资料查找摩擦，复用现有详情增加网页收藏与安全打开。已完成新旧软件回归，未验证用户效率或留存改善，版本尚未公开发布。
