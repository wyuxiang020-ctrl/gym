## 2026-08-10 — 修复触屏拖拽、扩充动作库、加成就感和宠物

**背景**:用户反馈训练计划页面没法调整动作顺序、动作库不够全、记录完没有成就感、宠物形象不好看。

- 训练计划的拖动排序改用 Pointer Events 重写(原来是 HTML5 `draggable`,在 iOS Safari 触屏上基本不生效,这是"没法调整顺序"的根本原因),同时给每天、每个动作加上序号
- 训练计划里每个动作下方显示对应练的肌群,方便新手理解
- 新增全局提示条(toast)组件,在导入计划、生成计划、选模板、添加动作时弹出确认
- 动作库从 40 个补充到 51 个(新增坐姿哑铃推肩、阿诺德推举、杠铃硬拉、保加利亚分腿蹲等常见动作)
- 当天训练全部勾选完成后,显示"已计入档案"横幅 + 每日不重复的鼓励语;打卡后也显示同样的鼓励语
- 宠物形象从抽象的"团子"重画成小熊猫,新增"每天限投喂一次竹子"的机制(此前可无限点击)

## 2026-08-06 — 训练与饮食流程改进(基于用户多轮反馈)

**背景**:这次改动量很大,是根据用户连续多轮具体反馈(共约 20 条)逐条落实的,主要方向是"降低记录门槛"和"让内容更真实可用"。

训练方面:
- 训练力量记录支持从预设动作库里点选,不再只能手打动作名
- 训练计划里可以直接选 5 套现成模板(此前只有规则生成一种方式)
- 新增"训练记录"页可以直接从训练计划导入当天动作、勾选完成,取代从零开始一条条添加
- 自然语言解析训练记录时,同名动作会合并进已有记录而不是重复新建
- 新增"动作库"独立页面,每个动作可查看肌群、动作要领、常见错误(卡片形式呈现,不是真实视频),并支持用户自己填一个视频直链
- 补充固定器械类动作(史密斯卧推、蝴蝶机夹胸等)
- 修了一个时区 bug:原来用 `toISOString()` 取"今天"的日期,在 UTC+8 等时区会算错

饮食方面:
- 新增"搭配菜谱"功能:选一种蛋白质来源 + 一种蔬菜,自动生成一道菜名和营养估算,可以用加减按钮调整克数,一键加入当天饮食(取代早期"点一下就显示 640 克"的不现实做法)
- 蛋白质/碳水/脂肪的食材参考从一两个选项扩充到 5-11 个
- 饮食记录新增拍照识别(先在浏览器端压缩图片再上传)
- 新增"按备注重新估算"功能:写一句"米饭只吃了半碗",AI 会据此调整原有估算,而不用自己手动改数字

整体设计:
- 从深色主题改成浅灰蓝底 + 白卡片 + 红色主色调的移动端设计,字体换成 Barlow / Barlow Condensed(标题大写)
- 底部由长列表改成 5 个标签的导航栏,加上滑动切换的图标和动效
- 新增打卡连续天数、月历热力图、宠物养成、成就勋章等游戏化元素

## 2026-08-05 — 首次提交:项目从零搭建

**背景**:从空文件夹开始,用 Vite 脚手架搭建,当天内完成了 4 个模块的基础功能并部署上线。

- 项目脚手架:Vite + React + TypeScript + Tailwind CSS v4,配置 PWA(`vite-plugin-pwa`),支持添加到主屏幕
- 数据层:`src/lib/store.ts` 统一封装 `localStorage` 读写,预留导出/导入 JSON 的备份功能
- 模块一(身体档案与训练计划):身体自测表单、BMI/BMR/TDEE 自动计算、按规则生成训练计划(不用 AI)、目标设定的健康边界提示
- 模块二(训练记录):力量训练(加减按钮调重量次数、勾选完成组)、有氧训练、MET 公式计算消耗热量、自然语言记录训练(调 `/api/parse-workout`)
- 模块三(饮食):文字/拍照/手动三种记录方式(拍照走 `/api/analyze-photo`,文字走 `/api/parse-meal`)、按备注重算(`/api/recalc-meal`)、每日蛋白质/热量目标与食物换算建议、饮水打卡
- 模块四(打卡签到):可配置的打卡定义、连续天数、月历热力图,断掉不做惩罚性设计
- 修复上线时的一个关键 bug:`/api` 下的相对导入必须带 `.js` 后缀,否则 Vercel 的 Node 运行时会在线上直接报 `ERR_MODULE_NOT_FOUND`(本地开发环境不会暴露这个问题)
- 创建 GitHub 仓库并部署到 Vercel,配置 `ANTHROPIC_API_KEY` 环境变量
