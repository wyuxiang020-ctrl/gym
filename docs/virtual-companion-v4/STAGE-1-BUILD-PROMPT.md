## 2 本轮范围与执行权限

只交付：一只原创简化拟人熊猫，一个独立实验入口，预设抬手动画，本机真实姿态驱动的简单抬手镜像，以及权限、失败与退出恢复。

本轮默认先用熊猫验证肩肘表达；海豹和其他动物属于后续适配，不同时开发。熊猫仍可在颜色、脸部和比例上微调，不需要重新讨论已确定的整体技术方向。

可核对版本与许可后安装必要开源依赖，可启动仅本地使用的前端实验服务、下载必要的官方本机姿态模型、运行软件检查。不要安装大型建模软件作为默认前置条件；已有工具不足时，先用可复现的程序化三维原型。

不读取密钥或 .env 文件，不调用 Gym 现有云端 AI 接口，不调用云端视觉/文本模型，不上传人体画面，不购买素材或订阅，不自动提交推送，不部署。摄像头只能在用户主动进入镜像模式、知悉用途并点击开启后请求权限。未经另行同意，不录制或保存人体照片、视频、可回放的原始姿态轨迹。

不实现器械识别闭环、第二角色、完整动作库、换装商城、AR、计次、动作评分、实时纠错、训练处方修改或新成长/喂养系统。动画、镜像及实验按钮不得写入训练完成、重量、热量等真实记录，更不能生成单次增肌或减脂克数。

## 3 视觉目标

参考 E:\gym\docs\virtual-companion-v4\character-direction\J-pixel-reference.png。
结构示意图为 E:\gym\docs\virtual-companion-v4\character-direction\construction-guide.png。
二者都是外观/结构意向图，不是已完成模型、骨架文件、动画或运行证据。如果文件无法读取，按下列文字规范继续，不猜测缺失图像内容。

- 保留像素参考的圆润身体、简洁五官、大色块、黑白熊猫识别特征和温柔游戏感。
- 可从约 2.5 至 3 头身尝试；这是设计起点，不是硬性人体比例。手臂适当加长，让肩、肘和手掌在抬手时可区分。
- 身体圆润但不做过度膨胀的肚子；脸部不采用写实人脸或复杂虹膜；不做成人健美体型。
- 首轮只用黑/奶白、一个低饱和运动配色及必要表情色块。可保留简单腕带，避免复杂服装遮住肩肘。
- 表面哑光、少量明暗层次、无真实毛发、无金属与复杂镜面反射。不把像素风改成方块堆砌的体素角色。
- 主视角正面或略微斜侧，优先用正交或弱透视获得接近二维的观感；实验检查可切换正面、斜侧面、侧面。
- 中文界面保持清晰，像素化只作用于角色画面，不作用于按钮、提示文字、摄像头预览或其他 Gym 页面。

## 4 制作真实三维角色

先做原生可旋转的三维网格和关节层级，再实现渲染风格。不能用一张 PNG、精灵序列、预渲染视频或角色整体上下跳动冒充三维关节运动。

优先采用可编辑、可复现的原创建模方式。首轮允许由低复杂度网格组成身体、头部、上臂、前臂和手掌，以真实肩肘枢轴建立父子层级。若使用分段网格和关节枢轴而非蒙皮骨骼，要在交付中明确说明，不把它称为完整蒙皮模型。若选择蒙皮，保留骨骼、权重与绑定姿势的源文件。

至少明确定义根节点、躯干、头部、左右肩/上臂、左右前臂和手部。统一坐标轴、角色正面方向、左右命名、单位及静止姿势。不要依靠任意 Euler 角直接套用而忽略父子坐标系和左右对称。

先在清晰模式检查垂手、抬手中段、抬手顶点以及侧面姿势；修复手臂穿过身体、肘部反折、枢轴位置错误和缩放异常，再调整像素风。

保留可复现生成脚本或建模源文件。使用导入资产时提交 GLB/glTF 及来源许可；程序化原型可先交付生成器和关节配置。若导出 GLB，必须重新导入验证结构、比例和动画，不只确认文件存在。

## 5 材质与两种渲染对照

优先使用 Three.js 与现有 React/Vite 结合，是否增加额外封装库以必要性决定，避免为单个实验重构全站。

同一个角色、同一套关节和动作，提供“清晰”和“像素”两种显示方式。清晰模式用哑光卡通着色，例如 MeshToonMaterial；像素模式在角色渲染结果上采用适度像素化，例如 RenderPixelatedPass 或经验证的等效方案。

从少量明暗层次、简单光照和低细节表面开始。GLB 的标准材质不等于运行时卡通着色，必要时在加载后显式替换/配置材质；不要假设建模软件里的材质会原样显示。

保留少量像素强度档位用于比较，并记录显示尺寸、设备像素比和实际配置。不要把截图缩小再放大冒充连续实时像素渲染，也不要宣称像素化天然省电。

两种显示方式对照时，角色、姿势、镜头、灯光、画布尺寸保持一致。检查抬手时肘部丢失、边缘闪烁、脸部色块粘连和前后遮挡。清晰模式必须可用，像素模式异常时可回退，并明确告知用户当前状态。

## 6 预设动作与真实镜像分别制作

预设模式：
- 只做空手的左/右抬手与放下，可包括短暂停留。
- 支持播放、暂停和重新开始。
- 动画驱动局部关节，角色根节点稳定，不用整体摆动代替手臂运动。
- 标为“预设动作实验”，不包装成专业健身动作教学。

镜像模式：
- 首轮限定单人、固定机位、上半身可见、简单左右抬手和放下。
- 采用本机姿态模型，例如 MediaPipe Pose Landmarker；先核对具体包版本、模型来源、许可及运行能力。
- 流程为相机帧 → 姿态关键点 → 可信度/时效检查 → 肩肘腕方向 → 角色局部关节旋转 → 渲染。
- 明确画面是否像镜子一样翻转，区分人体解剖左右与屏幕左右，用“只抬左手”和“只抬右手”分别核验，避免双重翻转。
- 相机单目深度不稳定时，先限制映射自由度；不要宣称任意三维运动捕捉。关节约束和平滑不能把错误或缺失观测伪装成正确跟随。
- 预设动画与镜像不能同时写同一关节。模式切换后清除旧状态、旧帧和晚到结果，不能继续播放预设动画假装跟随。
- 姿态推理与渲染频率分别管理，不堆积未处理相机帧，优先最新帧。确认实际 API 的同步行为后，选择合适的线程/调度方案；不能只添加一个 async 就声称不阻塞。
- 画面只有“跟随我的抬手”的能力；不自动判定动作正确、不计次、不写训练完成。

## 7 权限与生命周期

实现并验证：未开启、准备中、跟随中、跟踪丢失、失败和退出等清楚状态。

开启前说明相机用途、本机处理及不保存原始画面；请求 video，禁用 audio。处理权限拒绝、无相机、占用、非安全上下文、资源下载失败、模型初始化失败及渲染失败。

人物离开、关键关节遮挡、低可信度或帧过期时停止不可信驱动，显示暂停/丢失提示，可短暂保持最后可信姿势或缓慢归位；恢复可信输入后平稳恢复，不突然甩动。

退出镜像、切换为预设、页面隐藏或组件卸载时停止媒体轨道和推理；返回页面后由用户主动重启，不静默打开摄像头。处理权限请求或模型加载完成得比退出更晚的竞态，晚到的媒体轨道也必须停止。

退出实验后释放不再使用的渲染循环、监听器、worker、模型、材质/纹理、几何体与后处理资源。遵守 React StrictMode 的重复挂载行为，连续进入退出不能重复启动相机或后台推理。

## 8 与现有 Gym 隔离

独立实验入口按需加载角色和姿态资源，在挂载正常 AppContent、读取身体档案前分流。实验不要求建档、不导入合成训练记录，不复用会写入演示数据的 portfolio-demo 入口。

不要在普通首页预加载相机/姿态模型。核对 PWA 的预缓存规则与实际网络请求，动态 import 不等于绝不会提前缓存。模型/WASM 下载、公开 CDN 请求与上传人体画面分开记录；没有断网验证不能称为完全离线。

复用现有存储规则，不在角色组件直接新增个人 localStorage 读写。不要改模板、训练处方、四段真人视频、原宠物喂养、API、模型计费保护或数据迁移逻辑。

所有新证据另立版本，建议放入 E:\gym\evals\virtual-companion\v4-poc\；交付说明放在 E:\gym\docs\virtual-companion-v4\。按仓库要求同步维护受影响文档和 CHANGELOG。

## 9 验证方法与通过条件

开始性能测试前保存目标设备、浏览器、窗口尺寸、DPR、模型版本、模型输入尺寸、像素档位、测试动作与测量方法。

首轮建议使用如下工程目标，属于待验证目标而非保证：在明确记录的支持设备上连续运行 60 秒，角色渲染中位帧率至少 30 FPS，姿态更新中位频率至少 15 Hz；退出或隐藏页面后 1 秒内没有活跃相机轨道和继续推理。首次未达标结果必须保留，不能事后改阈值包装通过。

分别记录首次/缓存后的资源加载、模型初始化、推理 p50/p95、渲染帧耗时、关键点进入映射到应用关节的耗时、丢失/恢复次数与清晰度观察。不要把推理时间或关键点处理时间称为完整的人体动作到屏幕延迟。没有获准的端到端测量资料时，该指标写未测。

至少覆盖：
- 预设播放/暂停/重启和清晰/像素切换；
- 左手、右手、双手、放下以及身体不动时的抖动；
- 权限拒绝、无设备、初始化失败、加载中退出；
- 肩/肘/腕遮挡、离开画面、重新入镜；
- 模式快速切换、页面隐藏、重复进入退出和晚到结果；
- 实验不修改训练存储，既有模板、视频、重量编辑与保存重开没有相关回归。

固定关键点与故障注入用于可重复的软件测试，明确标为回放。相机不可用时，继续软件验证并列出未测项；不能用回放、假摄像头或动画冒充本机真实姿态。

桌面浏览器、手机尺寸模拟、真实手机、真实摄像头、作者自测和独立真人任务分别记录。手机模拟不是手机实测。未取得真机证据时，只交付受限实验，不宣布真机镜像已通过，也不自动进入下一阶段。

## 10 交付与停止

交付以下内容：
1. 可打开的本地实验入口、准确版本标签与启动/停止方法。
2. 实际三维资产或可复现生成器、关节命名/静止姿势、动画与渲染配置。
3. 同条件下清晰/像素的外观及动作对照，标注实际渲染；设计图单独标注。
4. 预设与真实镜像分别说明，正常流程和失败恢复证据；若有录像需区分真实运行/固定回放，且不未经同意保存人体画面。
5. 依赖、模型和资产的版本、来源、许可及可追溯文件哈希。
6. 测试首次结果、修复/重试、性能口径、历史完整性检查、未测项和限制。
7. 云模型调用数为 0 的执行记录；基础设施/流量未核算时如实标注，不能称所有成本为 0。

资产、渲染、预设动画、真实姿态、真机与教学审校应分别报告完成状态，不能只给一个“全部完成”。

达到“一只熊猫＋两种渲染显示＋预设抬手＋有限真实抬手镜像＋失败恢复”的首轮范围后，交付并停止扩展。若真实相机或设备条件不足，提交已完成的软件实验与具体未测项，不伪造验收，不擅自增加其他模块。
