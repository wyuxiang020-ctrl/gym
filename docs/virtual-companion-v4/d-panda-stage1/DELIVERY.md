## 打开与操作

- [原画动作与表情](http://127.0.0.1:4175/?companion-lab=1)：保留原有 11 段动作、12 张表情和减半后的时长；新增清晰与像素细／中／粗三档。
- [阶段一抬手互动](http://127.0.0.1:4175/?companion-lab=1&review=mirror)：先选择画面左手、右手或双手，播放 2.4 秒的抬起、保持、放下。支持暂停、继续、重新播放、进度和四个检查点。
- 进入「跟随我的抬手」后，由用户亲自点击「开启摄像头」。一人正对镜头，双肩、双肘、双手入镜，缓慢向身体两侧抬手。预览按镜子方向显示，与熊猫的画面侧对应。
- 停止摄像头、切回预设、页面隐藏、页面退出及组件卸载均释放轨道和 Worker；返回页面不自动恢复相机。相机等待权限期间退出，晚到的轨道也会停止。
- 本机服务若关闭，在 `E:\gym` 运行 `npm run dev:companion`，监听 `127.0.0.1:4175`。没有部署，也没有推送代码。

## 资源、网络与依据

`public/companion-assets/d-panda/design` 的七张 PNG 与交付包逐字节核对。新透明素材通过 `scripts/prepare-d-panda-interaction.mjs` 生成，完整嵌入原 PNG，只以 alpha 选择源像素；`interaction/manifest.json` 保存来源、方法与文件哈希。透明选区和网格位置是运行绑定资产，不能冒充新的官方原画。

MediaPipe 继续锁定 `@mediapipe/tasks-vision@1.1.0`；Pose Landmarker Lite float16 v1。既有本地模型与 WASM 的 9 项版本、SHA-256、来源和 Apache-2.0 许可证再次核对，记录在 `evals/virtual-companion/v4-poc/assets-1791456659098.json`。不以 CDN latest 作为运行依赖。

Worker 在载入 SDK 前安装网络限制，仅允许本站明确列出的模型、JS 和 WASM 静态 GET/HEAD，拒绝上传、重定向和其他网络通道；继续使用既有 Worker CSP。正式入口仅在用户主动启动后加载姿态资源。相机帧与人体关键点仅在内存处理，不保存录像或人体数据。

实现依据：[MediaPipe Web Pose Landmarker 官方指南](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)说明检测调用是同步的，应放入 Worker 避免阻塞界面；[Spine 网格官方指南](https://esotericsoftware.com/spine-meshes)作为原画纹理分区与网格变形方法参考。此处没有引入 Spine 运行时，也没有把其示例当作本项目资产。

性能口径在测量前固定：清晰和像素各连续 60 秒，画面中位数目标 ≥30 FPS；真人有效姿态目标 ≥15 Hz；停止释放目标 ≤1 秒。帧间隔代表实际绘制调用节奏，绘制提交耗时不等于 GPU 完成耗时。空白模型运行无法验证真人有效姿态频率，也不能据此宣称人体到屏幕端到端延迟合格。

最终生产构建的性能记录：`evals/virtual-companion/d-panda/stage1-performance-1791457530997/result.json`。Windows 桌面 Edge 154.0.4258.62、1200×1050 视口、AMD Radeon 610M / ANGLE Direct3D11。这里记录的是隔离自动化浏览器的绘制调用节奏，不是实际手机帧率或屏幕实际显示帧数。

| 60 秒窗口 | 实际绘制次数 | 帧间隔 p50 / p95 | 中位绘制频率 |
| --- | ---: | ---: | ---: |
| 清晰预设，480×480 | 14,152 | 4.2 / 4.8 ms | 238.1 Hz，达到 30 目标 |
| 中档像素预设，168×168 | 14,370 | 4.1 / 4.8 ms | 243.9 Hz，达到 30 目标 |
| 清晰 + 正式模型空白输入 | 14,258 | 4.1 / 4.9 ms | 243.9 Hz，达到 30 目标 |

空白模型这次资源加载 176 ms、初始化 170 ms，推理 p50/p95 为 15.9/18.6 ms；未检出人体，有效姿态频率为 0，**真人 ≥15 Hz 目标保持未测**。页面隐藏的软件释放观测为 6 ms，所有退出检查均在 1 秒窗口内结束；不能用它代替真实硬件指示灯测试。计时分辨率使单次底层 drawElements 提交 p50 显示 0 ms，这不代表 GPU 零开销；整帧主线程变形与提交的近期 p50 约 0.9–1.1 ms。

## 待实测
