## 最新续做：扫描与陪练完整衔接

统一入口：[器械扫描与训练](http://127.0.0.1:4175/?equipment-scan=1)。本地服务停止时，在 `E:\gym` 运行 `npm run dev:equipment`，再打开入口。启动不会自动上传照片或调用模型。

体验顺序：选择器械照片并主动识别（或手动选坐姿推胸机）→ 人工核对类别 → 查看适用型号资料 → 带入训练记录 → 添加 → **用熊猫陪练这个动作** → 开始当前动作 → 查看当前动作记录、填组数和重量并勾完成 → 组间计时 → 结束陪练查看已保存摘要。无档案先沿用原建档流程。

本轮修复与收尾：

- 扫描添加后可显式进入对应动作的陪练，即使当天第一个动作是划船，也不会误选它。已有陪练可切换到这次确认的动作；切换结束旧计时，保留正式记录。
- 进入后自动滚动并将键盘焦点放在陪练区域，遵循减少动态偏好；原「开始填写组数与重量」仍可单独使用。
- 添加失败不显示陪练交接按钮；动作被删除后会提示重新添加，重读最新记录完成恢复；同名动作不重复添加。
- 修复计时截止但页面尚未刷新时点击暂停可能卡在 00:00 的边界；此时直接进入待准备下一组，不自动标记完成。
- 陪练按钮和选择框至少 44px 高，修正 320px 窄屏关闭按钮断行。熊猫素材、动画与时长未修改，人体检测仍暂停。

本轮验证使用隔离的合成档案、合成图片和固定接口返回；桌面 Edge 的 320/390/1100 视口检查不等于真实手机测试。已有服务的配置状态和无效图片拒绝另作真实本地检查，未调用云模型。软件证据与明确未测项见 [集中验收交付](../equipment-scan-v1/INTEGRATION-DELIVERY.md)。

## 阶段三已完成内容

用户要求说明现状、下一阶段并直接执行。本轮选择阶段 3 的「已有熊猫 + 训练前和组间反馈」有限范围，不重新设计 IP、不扩展镜像或识别类别。原框架的第二角色/多骨架复用因用户指定保留熊猫且目前无实际需求，继续留待后续决定，不称为已实现多角色。

入口：[熊猫训练陪伴](http://127.0.0.1:4175/?training-companion=1)。正常训练页也有「开启熊猫陪练」按钮，默认关闭按需加载。已有个人档案进入训练记录，无档案沿用原建档流程。

操作：先添加或从器械扫描带入一个动作 → 开启陪练 → 选择当前动作 → 开始当前动作 → 在原记录中按实际填写并勾选完成 → 出现休息计时 → 准备好后点击下一组。陪练按钮不替用户填组、改变重量、勾完成或打卡。

休息可选 30/60/90/120 秒，按自己的安排调整；支持暂停、继续、每次延长 30 秒（最多剩余 10 分钟）、提前结束。结束计时不代表训练完成。页面隐藏停止动画和计时刷新，回来根据截止时间计算，不把后台节流误当更长休息；关闭陪练、切换动作、刷新或离开训练页面结束本次计时，正式记录保留。重新打开不会回放历史完成事件。

动画复用已认可的 idle/encourage/rest/celebrate 与减半时长，仅在对应状态变化时播放一次，不循环占用。系统减少动态默认静态，也可手动勾选静态形象；WebGL 不可用保留原图与全部记录/计时功能。不访问相机、姿态模型或云端接口。

结束摘要只按该日期当前动作中有效已完成的组计算：确认组数、待完成组数、已知重量的次数型容量、计时秒数、已确认重量缺失说明。包括此前已经保存的组，不冒充仅本次陪练新增的量，不计算增肌/减脂或额外生理指标。
