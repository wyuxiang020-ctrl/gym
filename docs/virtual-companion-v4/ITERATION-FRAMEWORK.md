## 产品目标与待验证假设

初始目标仍然是减少健身房内查器械、看动作视频、记训练等任务之间的软件切换。饮食记录和已有资料继续保留，但本轮不扩展营养模块。

优先用户假设是独自训练、对部分器械或动作不熟悉、愿意使用手机辅助但不希望增加操作负担的人。尚未确认该群体规模、付费意愿、长期留存或对动物角色的偏好。

待验证的价值不是角色是否可爱，而是它能否在具体器械前帮助用户找到适用教学、看懂下一步、继续训练，并准确保存。镜像互动的趣味性和长期陪伴价值也需要分别验证，不能由第一次体验推导长期使用。

## 已确定的方向与仍待确认的选择

| 项目 | 当前决定 | 实施边界 |
| --- | --- | --- |
| 虚拟 IP | 必须做，区别于旧小熊猫喂养 | 承担示范、训练上下文与组间引导，不另加喂养任务 |
| 角色选择 | 希望支持熊猫、海豹等动物及一定自定义 | 首轮建议单个拟人熊猫占位角色；多角色、名称、配色随后验证 |
| 手机扫描 | 必须做，主要识别器械 | 不以扫描人体作为默认训练入口；不凭图片自动写入完成记录 |
| 实时动作跟随 | 保留为重要探索，尽早验证 | 主动开启的实验模式，不等于标准教学、计数或纠错 |
| 真人教学 | 希望 IP 成为主要教学入口或与真人并行 | 现有真人参考保留；未审校动画不得宣称替代专业教学 |
| 训练后反馈 | 与个人档案和真实记录关联 | 显示记录事实与有依据的估算，不生成单次增肌或减脂克数 |

拟人熊猫是降低首轮骨架复杂度的建议，不代表用户已经批准其最终美术风格。若海豹保持短鳍等真实体型，可能无法清楚表达人体关节与握持关系；采用拟人四肢，或让它承担陪练而提供清晰教学参考，应在扩展该角色时确认。

## 目标流程与三种角色模式

目标流程：选择伙伴 → 拍摄器械 → 确认识别结果 → 选择支持的动作 → 查看适用示范与设置说明 → 开始训练 → 组间引导 → 编辑确认 → 保存 → 刷新重开 → 训练总结。

角色模式必须在界面上明确区分。

| 模式 | 动作或反馈来源 | 不得暗示的能力 |
| --- | --- | --- |
| 示范 | 预先制作的动画；进入正式教学前需内容审核 | 动画能播放不代表动作专业正确 |
| 陪练 | 当前训练状态、用户已确认记录、计时与预设内容 | 未启用观测时，不能声称看到用户动作或自动知道完成情况 |
| 镜像 | 摄像头估计人体姿态并映射到角色骨架 | 会复制用户动作和错误，不是动作评分、纠错或安全判断 |

首轮预设抬手动画仅验证播放与骨架，不命名为专业健身教学。正式教学可以与真人参考并存；必须核对变式、设备适用条件与内容来源。

## 首轮建议范围与完成标准

建议首轮采用一个原创简化的拟人熊猫占位角色。必要时使用授权清楚的免费资产，保存来源和许可；不购买模型或订阅。允许在确认后增加必要开源依赖，但先核查版本与许可，并以独立实验入口按需加载，不重构全站。

首轮包含以下工作。

1. 一个角色，两种清楚区分的实验状态：播放预设抬手动作，以及跟随我的抬手。
2. 预设动作支持播放、暂停和重新开始；不作为正确健身动作教学。
3. 镜像仅验证单人固定机位下左右抬手和放下，不增加计次、负重识别、动作评分或训练完成写入。
4. 请求摄像头前解释用途；仅在用户主动进入并授权后启用。退出、切换模式、关闭页面时停止相机使用，不在后台继续录制。
5. 拒绝权限、没有设备、资源加载失败、姿态跟踪丢失等均有明确提示和退出路径。低可信或丢失时停止不可信驱动，不假装仍在识别。
6. 默认不保存或上传人体原始画面；需要录屏或使用自拍视频作测试资料时，另确认素材用途和留存范围。测试优先使用可授权的独立样本，不读取个人相册或健康档案。
7. 原有模板、视频、编辑确认、重量状态和保存重开不受影响；原记录不被实验按钮修改。
8. 记录目标环境下的加载耗时、可得帧率、响应延迟测量方式、跟踪失败和资源释放情况。测量前定义方法与阈值，不事后只挑好看的数值。

首轮不调用云端视觉或文本模型，云模型调用数和费用应为零；本机姿态模型运行与云模型调用分开记录。基础设施或流量账单未核算时写未核算，不能把模型零费用称为全部零成本。

验收必须报告能力状态，而不是只报告能构建。桌面浏览器、手机窗口模拟、真实手机和真实摄像头分别列出。若当前无法取得真机或真实摄像头，不用固定视频回放冒充实测；仍可交付受限实验、软件测试和待验证项，但不得宣布真机镜像已验收，也不得因此自动进入下一阶段。

## 器械阶段的设计约束

下一阶段优先选择作者能够提供或取得获准样本的一类常用器械；坐姿推胸只是候选，不默认已选定。器械照片、标牌、型号和预期动作应可追溯，不把模型自己的描述当识别真值。

识别仅返回受支持候选或未知。相似器械、模糊画面和非器械图片均应覆盖；补拍、手动选择和取消是正常路径。结果未经用户确认，不启动相应记录写入。

正确识别名称与正确匹配教学分开验收。动画和真人参考都要核对动作变式与器械适用条件。缺少有使用权限的素材或内容审核时，保留明确实验标记，不能把占位动画包装为专业教学完成。

继续沿用现有访问与预算保护；在真实云调用前明确单次实验请求上限、预算和允许上传的数据。失败、重试与取消也计入请求与成本记录，不只统计成功结果。

## 训练后反馈与安全边界

用户希望看到训练成果，但个人档案不能把一次训练转换为真实的增肌克数或减脂克数。仅输出确认过的动作、组数、次数、重量与时长；热量明确标为估算，说明实际时长或默认假设。体重和体成分趋势只按其实际测量来源表达，不把重量增长自动解释成肌肉增长。

虚拟角色的外观变化若将来采用，必须明确是产品表达，不对应用户已测得的生理变化。首轮不实现新的成长、惩罚或喂养机制。

不承诺替代教练、康复指导或安全判断，不要求用户为测试尝试陌生负重。镜像验证先使用空手简单动作，不能把摆机位变成每次训练的强制步骤。

## 验证记录与历史保护

新证据使用独立目录，例如 evals/virtual-companion/v4-poc/；新交付放在本目录。路径可由实施时核查后细化，但不得覆盖旧 20 条、后续保存评测或 V3.3 的脚本与历史结果。需要改进旧测试时新增版本并说明变化。

每条新记录至少包含：版本或源码哈希、时间、设备和浏览器、测试类型、输入及来源、预期行为、首次结果、失败原因、重试和修改后结果、耗时口径、最终存储核查、可得费用及未测项。比较前后结果时固定资料范围；留一组未参与调优的输入作最终检查。

| 证据类型 | 能说明什么 | 不能代替什么 |
| --- | --- | --- |
| 自动化软件测试 | 状态切换、取消、失败恢复、资源释放、保存一致性 | 真人任务体验、真实识别质量 |
| 固定响应或关键点回放 | 已知输入下的界面和映射逻辑 | 真摄像头检测、真模型识别 |
| 本机真实姿态模型 | 指定设备和资料下的关键点与镜像表现 | 专业动作正确性或所有手机稳定性 |
| 云端真实模型调用 | 指定器械样本上的识别、拒判与成本 | 默认自动写入真实训练事实 |
| 作者自测 | 作者个人的任务经历与问题发现 | 独立参与者结论、市场规模或留存改善 |
| 真人任务测试 | 由实际参与者按脚本完成的具体任务证据 | 未执行时不得补成模拟结果 |

原真人测试脚本继续保留未测状态，不以招募为所有后续工作的前置条件。没有真实样本与参考答案，不报告准确率；没有用户测试，不宣称效率、满意度或留存提高。动画专业审校与一般用户测试是不同工作，不能互相替代。
