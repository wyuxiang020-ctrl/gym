PRODUCT REQUIREMENTS / 2026.10.09

Gym 产品需求文档

从认识器械到记录进步的日常训练工具
负责人：王誉翔 · 版本：作品集整理版 / 当前实现基线

产品目标

让用户在健身前、中、后找到相应入口，减少重复描述已知信息；让 AI 的建议可检查，让正式记录只包含用户确认的内容。

1. 用户与问题

来源为个人使用经历、作者转述的同学与朋友意见及实际迭代反馈。尚无正式访谈样本数或量化任务测量。

使用情境（设计假设）要完成的事对应入口
不熟悉器械的新手确认是什么、找适用资料、开始记录扫描 / 手动确认 → 型号资料 → 训练
已有固定训练安排复用计划、核对组次、回看上次重量计划 → 当天记录 → 逐组确认
训练后补记饮食整理零散描述或餐食照片，检查份量饮食输入 → 可编辑草稿 → 保存

2. 本轮范围

包含：首页训练概览、计划与动作、训练记录、AI 辅助录入、饮食、身体趋势、单器械资料路径、熊猫反馈与休息计时、历史与备份。

暂缓：人体动作检测、自动纠错、三种运动试作、账号/云同步、社交排行。器械仅坐姿推胸机；专业指导不由 AI 自行补写。

CORE FLOWS

3. 主要使用路径

A · 到健身房后确认器械

主动选照片或手动选择 → 展示候选 → 用户确认类别 → 核对型号与适用资料 → 带入动作 → 显式添加记录。拒绝权限、上传失败或无法识别时保留手动入口，不自动写入。

B · 完成当天训练

查看计划或已有记录 → 核对重量与组次 → 逐组确认 → 保存成功 → 若开启陪练则进入休息 → 准备好后继续。计划导入不勾选完成。

C · 补记训练或饮食

用户主动提交文字或照片 → 显示等待、支持取消/失败恢复 → AI 返回可编辑草稿 → 突出缺失和不确定内容 → 用户核对确认 → 保存到当前浏览器。

D · 回看与备份

首页查看当日和本周实际完成 → 选择日期看历史 → 按日期读测量值 → 需要换设备时导出/导入备份。网页与桌面安装版不是云同步。

4. AI 与人的分工

内容谁负责规则
整理自然语言、餐食照片AI 生成候选不确定信息保留提示，不编造时长/重量
计划复用与数值计算既有规则可解释、可重复，不强制调用 AI
真实完成与正式保存用户确认AI 返回不能代替完成勾选
器械教学核对型号后的现有来源不由模型扩写未经审校的训练处方

FEATURES & ACCEPTANCE

5. 功能要求与验收

模块应有行为通过条件
首页当天训练与主操作优先无记录显示可执行入口，有记录展示实际完成
计划可复用、可修改导入后不自动完成；重复导入明确选择
训练组重量、次数/时长、完成独立编辑后确认；保存刷新后仍一致
缺失重量自重、未知、已知分开明确确认缺失后可保留完成；容量排除缺失项
AI 草稿可改、可取消、可恢复确认前不计入记录；失败保留原输入
饮食份量与营养可核对估算有提示；修改克数后合理联动
器械候选与人工确认不支持时说明；手动路径始终可用
熊猫陪练准备/休息/结束反馈只响应当前动作成功保存事件，结束不补齐组数
休息计时可暂停、延长、结束后台恢复按剩余时间显示；不替用户开始下一组
历史与备份保存可回看、导入可检查无效导入不覆盖原数据，失败有说明

6. 交互原则

手机优先；主操作保持足够触控面积；保存中、失败、已完成明确区分；放大文字和静态偏好可用；不以动画遮挡记录、计时与错误信息。

EDGE CASES & VALIDATION

7. 异常与恢复

触发产品响应
照片权限拒绝 / 服务不可用说明原因，保留文件选择、手动确认或重试路径
AI 失败 / 超时 / 结果不完整保留文字，允许修改重试；必要信息补齐或明确缺失确认后保存
浏览器保存失败保留编辑，不显示保存成功，不触发休息；提供备份入口
撤销完成 / 切换动作 / 关闭陪练清理对应内存计时，保留已存记录，不跨动作响应旧事件
断网已缓存页面和本地记录按缓存状态可用；识别、外部视频需联网

8. 验证与成功标准

已经可验：入口能完成任务、确认前后状态一致、刷新能回看、失败可恢复、错误数据不静默写入、手机视口无横向溢出。

待招募真人测量：从器械入口找到适用资料的完成情况、完成一组记录所需步骤、AI 草稿修改次数与原因、是否愿意自然复用。先收集基线，再设改进目标；不预填成功率。

待补：真实照片识别质量、真实手机权限/相机/键盘、专业教学审校。现有合成模型评测和浏览器回归不替代这些结论。

9. 当前状态与下一步

基础版本已发布；新版视觉与本次动画撤下在本地实现。下一步优先观察真实任务的卡点，再确定是否扩大器械范围或重新制作运动素材。暂不增加新动作库。
